# /diary

呼び出されたら、以下を順に行う。

## 1. 今日の作業内容を集める

- `git log --since=midnight --oneline`（または当日分のコミット）と `git status` / `git diff` で、今日行った実装・変更点を把握する。
- コミットされていない作業も対象に含める。
- 今回の会話の中で発生した詰まりどころ（エラー、設計判断で迷った点、原因調査に時間がかかった点など）を振り返る。特に詰まりがなければ正直に「特になし」と書く。捏造しない。
- TodoWriteのタスクリストや会話の流れから、次にやるべき具体的な項目を洗い出す。

## 2. 日記.mdに追記する

- 場所: リポジトリルート（`/home/arata/Rhing/Applications/DaiDai/日記.md`）。
- ファイルが無ければ新規作成。あれば**新しいエントリを先頭に追記**（新しい日付が上に来る形）。ただし下記のTODOブロックは日付エントリより前（ファイル最上部）に置く。
- 1エントリのフォーマット:

```markdown
## YYYY-MM-DD

### 実装内容
- ...

### 詰まったところ
- ...（無ければ「特になし」）

### 次にやること
- ...
```

- 同じ日に複数回 `/diary` が呼ばれた場合は、その日のエントリに追記・統合する（同日で見出しを重複させない）。
- 内容は今日の会話・git履歴から確認できる具体的な事実のみ書く。推測や一般論で埋めない。

### 最上部のTODOブロック

「この後何をするのか」が日記.mdを開いた瞬間に分かるよう、全ての日付エントリより前（ファイルの一番上）に`# TODO`ブロックを常設する。

```markdown
# TODO
- [ ] 項目1
- [ ] 項目2

---

## YYYY-MM-DD
...
```

- `/diary`実行のたびに、このブロックの中身を**今回追記した「次にやること」の内容で丸ごと置き換える**（過去の古い項目を積み上げていかない。「常に最新の次にやること」を表示する場所であり、履歴は各日付エントリの「次にやること」側に既に残っている）。
- ブロックが無いファイル（初回・移行前）には新規作成する。
- 既存のブロックがあれば、`# TODO`から直後の`---`までの範囲を丸ごと今回の内容に差し替える。

## 3. コミット・push

日記.mdおよびFlutterプロジェクト一式（`lib/`, `android/`, `ios/`, `macos/`, `linux/`, `windows/`, `web/`, `pubspec.yaml`, `firebase.json`, `firestore.rules`等、リポジトリ内の変更全般）の更新は事前承認済みの操作。確認を取らずに以下を実行する。

```bash
git add -A
git commit -m "日記: YYYY-MM-DD"
git push
```

- upstreamが未設定の場合は `git push -u origin main`（または現在のブランチ）で設定する。
- `git add -A`する前に`git status`で内容をざっと確認し、`.gitignore`で想定通り除外されているか（`build/`, `.dart_tool/`など）だけ確認する。シークレットらしきファイル（トークン・鍵ファイルなど）が含まれていないかにも注意する。心当たりのない不審なファイルがあれば、コミットせずユーザーに報告する。
- pushが失敗した場合（コンフリクト、リモート未到達など）は、force pushなどで無理に解決せず、状況をユーザーに報告する。
